# 开发阶段与验收清单

原则：**每阶段都可运行、可解释、有真实数据验收。**
路线优先级：**Agent 工程深度优先**，豆包式功能按阶段补齐；本阶段先不排具体日期。

## 阶段总览

| 阶段 | 主题 | 状态 | 核心产出 |
|---|---|---|---|
| P0 | 基础主链路 | **已完成** | 会话、消息、SSE、停止/重生成、MySQL、错误/日志 |
| P1 | 知识底座 | **已完成** | 文件上传/解析/切块/关键词 RAG、Tavily+SerpApi 联网搜索、来源 |
| P1.5 | 质量硬化 | **已完成（有已知边界）** | 真实文档/搜索评测、正文抽取、查询规划、来源多样性、延迟/成本门槛 |
| P2 | **Agent 核心** | **下一步** | 工具协议、注册表、function calling、有界循环、tool_run 日志、工具状态 UI |
| P3 | 记忆与个性化 | 计划 | 长期记忆、设置、创作模式、自定义指令 |
| P4 | 多模态 | 计划 | 图像理解、语音输入/朗读；不做图像生成/编辑 |
| P5 | 产品化 | 计划 | 多模型切换、认证/多用户、部署、限流、可观测性、CI |
| P6 | 进阶 Agent | 计划 | MCP 工具/插件、工作模式、可选多 Agent |
| P7 | 暂缓 | 暂缓 | 视频、图像生成/编辑、训练/微调、社交/支付 |

> P1.5 不是新功能阶段，而是 P1 的验收门槛：没有真实数据评测，不能把 P1 标记为完成。

## P0：基础主链路（已完成）

**目标**：跑通可用的聊天主链路。

**范围**：会话 CRUD、消息持久化、上下文组装、DeepSeek/mock adapter、SSE 流式、Markdown、停止、重新生成、自动标题、统一错误、请求 ID、健康检查。

**不做**：文件、搜索、记忆、图片、Agent。

**验收**：两轮以上聊天保持上下文；刷新恢复；会话隔离；停止/失败状态正确；密钥不进入前端/Git。

**学习点**：REST、SSE、异步生成器、SQLAlchemy 事务、上下文窗口、异常归一化。

**作品产出**：可演示聊天、架构图（前端 → SSE → 服务 → provider → MySQL）。

**依赖**：MySQL、DeepSeek key（或 mock）。

## P1：知识底座（已完成）

**目标**：让助手能基于文件和联网信息回答，并给出可追溯来源。

**范围**：

- 文件：上传、私有存储、PDF/DOCX/TXT/MD/代码解析、切块、关键词 RAG、文件来源、错误状态、删除级联。
- 搜索：Tavily 主源 + SerpApi 可选 fallback、时效/主题识别、去重、失败降级、`tool_status`、网页来源、发布日期。

**不做**：向量检索、OCR、图片、页面正文抓取、多引擎扇出。

**验收**：

- 上传支持的文件后能查看状态；总结/细节问题能召回并引用片段。
- 用户不能读取别人的文件；删除会话清理附件/分块/磁盘文件。
- 联网问题返回真实可点击来源；未配置/失败时明确提示，不伪造来源。
- 真实数据用例：至少一份真实 DOCX 总结、一个时效新闻 query、一个失败降级场景。

**学习点**：multipart、MIME/魔数、解析器适配、切块、关键词检索、RAG 提示词、来源事件、搜索 API、提示注入。

**作品产出**：文件问答 demo、联网新闻 demo、来源/降级截图。

**依赖**：P0；Tavily/SerpApi key（可选）。

### P1 已识别但未完成的质量问题

- 搜索只读摘要，未读正文；宽泛新闻容易集中到单一热点。
- 查询理解浅：显式日期、“最近/最新/近期”覆盖不足。
- 来源质量/多样性未排序；同一文章可能重复。
- 文件关键词检索对同义改写/跨语言召回有限；扫描件/图片不 OCR。

## P1.5：质量硬化（已完成，有已知边界）

**目标**：把 P1 从“能搜到”提升到“可日常使用”，并建立真实数据评测。

**已完成部分**：

- 搜索：规则 + LLM 兜底查询规划、显式日期/裸“最近”、宽泛新闻子查询、过取→去重→权威/多样性排序、Tavily 正文抽取、日期过滤、TTL 缓存、总超时预算。
- 文件：DOCX/Markdown 标题路径、heading-only 可检索、表格保序/表头重复、overlap 预算、常见二字过滤、IDF、按附件取候选、内容去重、excerpt 连续编号、来源只含实际 excerpt、引用校验。
- 评测：`scripts/eval_p15.py`（offline/search/e2e），真实文档/query fixtures；离线 4/4、真实搜索 5/5 通过。真实 E2E 文件用例通过；宽泛新闻出现单源时模型会明确说明来源不足。

**已知边界**：SerpApi 备源仍只有摘要；宽泛新闻可能单源；没有自建页面抓取器；旧上传不会自动重索引；关键词检索对同义改写仍有限。

**范围**：

1. **评测集**：真实 DOCX/PDF/TXT + 总结/细节/对比问题；时效/实体/常青/实时数据 query；记录期望与失败模式。
2. **搜索正文抽取**：对 top 3–5 结果读取正文（Tavily raw content 或本地抽取），每条截断并带域名/日期；列表页/导航页降权。
3. **查询规划**：识别显式日期、“最近/最新/近期”、新闻/实体/常青/实时数据；宽泛新闻拆 2–3 个子查询。
4. **来源质量/多样性**：官方/一线媒体加权；每域名限 1–2 条；标题+域名去重；提示词要求覆盖多类别、区分已确认/待核实。
5. **结果日期过滤**：解析发布日期；超出时间窗的结果降权/过滤。
6. **延迟/成本门槛**：单轮搜索 + 正文抽取的耗时/费用上限；简单问题只搜一次。

**不做**：向量库、多引擎扇出、全站爬虫。

**验收**：上面 5 类 query 在评测集中达到“来源新鲜、类别覆盖、引用可点、无明显编造”；失败场景有明确降级。

**学习点**：检索评估、查询重写、正文抽取、来源排序、成本/延迟权衡。

**作品产出**：搜索质量对比报告（before/after）、评测脚本、失败案例复盘。

**依赖**：P1。

## P2：Agent 核心（下一步，重点）

**目标**：从“预检索管线”升级为“模型决定调用工具”的单 Agent 循环。

**范围**：

1. `Tool` ABC：name、description、JSON Schema、`run(args, context)`、超时、输出上限。
2. `ToolRegistry`：白名单、参数校验、统一错误、启停。
3. 首批工具：`calculator`（安全表达式解析，禁止 `eval`）、`document_search`、`web_search`（复用 P1）。
4. Provider tool calling：OpenAI 兼容 adapter + mock；模型不支持时结构化输出兜底。
5. 有界循环：最大步数（`AGENT_MAX_TOOL_CALLS`）、单工具/总超时、取消传播、失败回填。
6. `tool_runs` 表与日志：参数摘要、结果摘要、状态、耗时、错误；SSE `tool_status`。
7. 前端工具状态 UI；来源与最终回答持久化。

**不做**：任意 Shell/代码执行、任意本地路径、无人值守长任务、多 Agent。

**验收**：

- 模型能按 schema 请求工具；非法参数/未知工具被拒绝。
- 算数、查文件、查网页、组合任务各至少 2 个真实场景通过。
- 超过步数/超时/工具异常能安全结束并说明原因。
- `tool_runs` 可追溯；前端能看到工具执行状态。
- 至少 10 个评测场景：该用工具的、不该用的、多步的、失败的。

**学习点**：Function/Tool Calling、JSON Schema、Agent 控制循环、白名单/最小权限、超时/重试、可观测性、失败恢复。

**作品产出**：多工具 demo、工具协议文档、`tool_runs` 日志截图、Agent 评测报告。

**依赖**：P1/P1.5；模型 tool calling 真实验证。

## P3：记忆与个性化（计划）

**目标**：让助手记住稳定偏好/目标，并支持创作模式。

**范围**：

- `user_settings`、`user_memories` 表与迁移；默认关闭。
- 记忆提炼（节流/成本限制）、查看/编辑/删除/关闭、按相关性注入。
- 创作模式提示词模板（写作/润色/总结/翻译/头脑风暴/学习辅导）+ 前端选择器。
- 自定义指令；设置页。

**不做**：把整段对话当记忆、默认开启、跨用户共享。

**验收**：默认关闭；开启后才写入/注入；关闭后停止；删除后不再召回；模式输出确实不同；记忆不泄露到其他用户（多用户后）。

**学习点**：数据生命周期、隐私/最小化、提示词模板、上下文注入、成本控制。

**作品产出**：记忆管理 demo、开启/关闭对比、创作模式对比。

**依赖**：P2（记忆可作为工具/上下文）。

## P4：多模态（计划）

**目标**：支持图像理解和单轮语音输入/朗读；**不做图像生成/编辑**。

**范围**：

- 图片上传、视觉消息格式、能力探测、视觉模型 adapter；不支持时禁用。
- 语音输入（ASR）→ 文本消息；语音朗读（TTS）→ 回答音频；先单轮，不做连续语音。
- 多模态资源的大小/格式/超时/成本限制。

**不做**：图像生成/编辑、视频、连续语音对话、声音克隆。

**验收**：不支持视觉时前端禁用；图片问答可引用图片内容；语音往返可用；失败有明确提示。

**学习点**：多模态消息格式、能力探测、媒体存储、ASR/TTS、成本/延迟。

**作品产出**：看图问答 demo、语音问答 demo。

**依赖**：P2/P3；视觉与语音服务选型。

## P5：产品化（计划）

**目标**：从本地单用户走向可部署、可隔离的产品。

**范围**：多模型切换、认证/多用户、部署（Docker/反向代理/HTTPS）、限流、日志脱敏、用量/成本记录、备份、CI。

**不做**：支付/计费、复杂权限体系、跨区域高可用。

**验收**：两个用户数据隔离；重启后数据库/文件仍在；密钥不泄露；限流生效；CI 跑单测/集成/前端检查。

**学习点**：认证授权、部署、可观测性、限流、备份、CI。

**作品产出**：部署文档、架构图、隔离/限流演示。

**依赖**：P0–P4。

## P6：进阶 Agent（计划）

**目标**：接入外部工具生态，支持更长任务。

**范围**：

- MCP 客户端/工具：schema、权限、超时、审计与本地工具统一。
- 插件 manifest、启停、权限声明。
- 工作模式：长任务、计划、产物（文档/表格/报告）、人工确认点。
- 可选多 Agent：仅在单 Agent 评测稳定后评估。

**不做**：任意 Shell/代码执行、无人值守高风险操作、为了多 Agent 而多 Agent。

**验收**：MCP 工具可发现/调用/失败降级；工作模式有计划/产物/中断恢复；权限最小化。

**学习点**：MCP、工具生态、任务规划、长任务状态、人工介入。

**作品产出**：MCP 工具 demo、工作模式 demo、Agent 轨迹报告。

**依赖**：P2–P5。

## 质量门禁

每个阶段完成前必须回答：

1. 功能验收：真实用户路径是否跑通？
2. 工程验收：错误/超时/取消/越权是否有明确行为？
3. 真实评测：是否用真实文档、真实搜索、真实模型（或明确标注 mock）跑过？
4. 可观测：失败时能否从日志/工具记录/请求 ID 定位？
5. 成本/延迟：是否有上限和记录？

**禁止**：只用 fake provider 的单测绿灯就宣布阶段完成。

## 开发方式（VSCode + Claude Code）

1. **验收标准先行**：先写功能/工程/评测三类验收，再写代码。
2. **plan mode**：让 Claude Code 先读代码和文档、给出方案，再执行；避免一次性生成大量难解释代码。
3. **垂直切片**：一次做一个端到端可运行的小功能（API + service + 前端 + 测试）。
4. **测试分层**：纯函数单测 → MySQL 集成测试 → 真实数据评测；MockTransport/fake provider 只验证流程。
5. **小步提交**：每个可运行切片提交一次；提交信息说明行为变化。
6. **文档同步**：状态/API/表结构变化同步到 `docs/`；本阶段优先保证 PRD/路线图/README 一致。
7. **密钥边界**：只放 `backend/.env`（Git 忽略）；不粘贴到聊天、不写进前端 `VITE_*`、不提交。
8. **评审**：先修正确性，再做简化和性能；不要为了“看起来完整”堆功能。

## 作品产出与面试讲点

每阶段至少产出：

- 可演示 demo（真实输入/输出 + 失败场景）。
- 架构图/流程图（上下文组装、搜索链路、工具循环）。
- 评测记录（用例、指标、失败模式、修复）。
- 面试讲点：
  - 为什么先关键词 RAG，而不是一上来向量库？
  - 搜索质量怎么评估？为什么只搜摘要不够？
  - 工具调用怎么保证安全/可恢复？步数/超时怎么设？
  - 如何防止伪造来源和提示注入？
  - 单用户到多用户的隔离边界怎么补？

## 风险与开放问题

- 搜索质量/正文抽取/来源排序可能比预期耗时；先做评测再优化。
- 模型 tool calling 能力因 provider 而异；必须用真实响应验证。
- 语音/视觉服务选型、成本、网络可用性未定。
- 范围膨胀：豆包式功能很多；Agent 深度优先，其他按阶段补。
- 校招/实习准备期有限：每阶段必须有可演示产出，不能长期停留在基础设施。
