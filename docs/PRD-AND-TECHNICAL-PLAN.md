# AI 助手 V1：产品需求规格与技术实现方案

版本：0.1（需求基线草案）  
目标：边开发边学习，形成可演示、可部署、能解释设计决策的 AI 应用项目。

## 1. 产品定位

开发一款网页版个人 AI 助手，交互参考豆包/ChatGPT：左侧会话列表，中间消息区，底部输入框。第一版优先覆盖主要日常能力，后续再增加语音、图片生成、代码执行等高级能力。

### 已确认决策

- 平台：先 Web，后续再考虑桌面端。
- 用户与目标：先作为计算机专业项目与求职作品；本地单用户开发，后续补注册登录、云同步。
- 前端：Vue 3 + TypeScript。
- 后端：Python + FastAPI。
- 数据库：MySQL。
- 模型：第一阶段一家服务商；设计统一模型接口，后续支持替换/扩展；API 供应商尚未选定。
- 界面：左侧会话列表、中央聊天区、底部输入区。
- 联网搜索：模型判断问题是否需要搜索；回答尽量展示来源标题与链接。
- 文件：PDF、DOCX、TXT、Markdown、代码文件、图片。
- RAG：解析文本、切块、检索相关片段，再让模型回答；第一版先做轻量关键词检索，语义向量检索之后再评估。
- 长期记忆：用户启用之后才自动提炼；用户能查看、编辑、删除和关闭。
- 创作：写作、润色、总结、翻译、头脑风暴、学习辅导等预设模式。
- Agent：先做搜索、文件检索、计算器等受控工具；复杂任务规划后续再做。
- 成本：尽量使用免费额度、可控 API 用量；不能承诺所有外部 API 或云服务器一直免费。

## 2. 第一版功能边界

### P0：最先完成的可运行主链路

1. 新建会话、列出历史会话、切换会话、重命名和删除。
2. 多轮聊天：保存用户消息和助手回复，按会话读取历史。
3. 流式输出：回答逐步显示；支持停止生成。
4. Markdown 渲染、代码块展示/高亮、复制回答、重新生成。
5. MySQL 持久化；基础参数配置在后端环境变量中。
6. 统一错误结构、请求日志、健康检查。

### P1：第一版主要 AI 能力

1. **LLM 统一调用层**：统一文本聊天与流式接口；视觉、工具调用按供应商能力启用。
2. **联网搜索**：模型/后端工作流决定是否调用搜索工具；来源以标题和 URL 附在回答中。必须先选择搜索服务后才可真实联网。
3. **文件问答（轻量 RAG）**：上传文件、提取文本、分块、关键词检索 Top-K 片段，并把片段作为带来源标记的上下文交给模型。文件只在当前用户可见。
4. **图片理解**：上传图片并交给支持视觉输入的模型。模型服务未选定前先完成上传与接口契约；运行时通过能力探测判断是否支持。
5. **长期记忆**：设置页默认关闭；用户明确启用后，才尝试从对话中提炼稳定、有用的偏好/目标等信息；支持查看、修改、删除和禁用。记忆提炼可能增加一次模型调用与费用。
6. **创作模式**：聊天输入可选择通用聊天、写作、润色、总结、翻译、头脑风暴、学习辅导；初期使用提示词模板，不训练模型。
7. **基础 Agent 工具**：计算器、文档检索、联网搜索（服务选定后）。显示工具执行状态和来源。工具循环设置最大步数和超时。

### P2：明确暂缓

- 语音输入、语音朗读、连续语音对话。
- AI 图片生成与图片编辑。
- 视频理解/生成（本项目不纳入计划）。
- 任意代码执行/终端控制/桌面自动化。
- 完整多模型切换管理界面。
- 注册登录、第三方登录、云端同步、多用户权限体系（但数据表先预留 user_id）。
- 云端对象存储、生产级运维监控。
- Embedding 语义检索与独立向量数据库；轻量关键词检索验证后再决定。
- 扫描版 PDF 的 OCR、复杂表格还原、大文件异步处理队列。

## 3. 非功能要求

- **安全**：模型密钥只放后端；上传文件校验扩展名/MIME/大小，生成内部存储名，不使用用户文件名拼接存储路径；不得执行用户上传代码。
- **隐私**：记忆默认关闭；数据访问按 user_id 过滤；第一阶段不开放公开互联网访问。未完成认证/限流/HTTPS 前不能把开发版直接公开给多人使用。
- **稳定性**：模型调用有超时、异常归一化；SSE 断开后尽量取消上游请求，并标记未完成的助手消息。
- **成本**：限制输入文件大小、上下文片段数量和最大输出 token；记录模型名与 token 用量（服务商能提供时）；错误信息不泄露密钥。
- **可维护性**：API 层、业务服务、数据访问、外部适配器分离；用数据库迁移管理表结构。
- **可测试性**：核心服务可用 mock LLM/搜索服务进行测试，不依赖真实 API 才能跑单元测试。

## 4. 架构与模块职责

### 前端（Vue 3 + TypeScript）

- `views/ChatView.vue`：组织页面。
- `components/chat/`：会话列表、消息列表、消息气泡、输入区、来源展示、工具状态。
- `stores/`：管理会话、当前消息和用户设置等状态。
- `api/`：集中封装后端 API；流式响应使用浏览器 `fetch` + `ReadableStream`，普通 CRUD 可用 `fetch`。
- `types/`：前后端数据契约对应的 TypeScript 类型。
- `router/`：路由；首版可只有聊天页和记忆管理/设置视图。

### 后端（FastAPI）

- `api/v1/endpoints/`：HTTP 层，只做参数校验、调用服务和返回响应。
- `schemas/`：Pydantic 请求/响应模型。
- `services/`：聊天、会话、文件、记忆、搜索、Agent 等业务流程。
- `repositories/`：SQL 查询与持久化。
- `models/`：SQLAlchemy ORM 表映射。
- `ai/providers/`：统一 LLM 接口与具体服务商 adapter；在服务商选定前，不创建虚构的真实供应商实现。
- `rag/`：解析器、分块、检索与 RAG 流程。
- `tools/`：工具基类、注册表、计算器、文档检索、搜索封装。
- `storage/`：本地文件存储接口；以后可增加对象存储 adapter。
- `core/`：设置、日志、错误处理、安全相关配置。

## 5. 核心业务流程

### 普通聊天

1. 前端创建/选择 conversation。
2. 用户提交内容及可选 attachment IDs、创作模式。
3. 后端校验会话归属，先保存用户消息。
4. `ChatService` 读取最近对话上下文、可用记忆（仅在启用时）、以及必要的系统提示词。
5. `LLMProvider` 产生流式 token；后端通过 SSE 转发。
6. 正常结束时保存完整助手消息和可用的 token 用量；如果中断，则记录中断状态。

### 联网搜索

1. 后端决定是否进入搜索流程（首版可以由模型工具调用或简单意图判断触发）。
2. `SearchProvider` 查询网页，返回标题、URL、摘要等结构化结果。
3. 把受限数量的搜索结果交给模型综合。
4. SSE 发出 `source` 事件，前端展示来源链接。
5. 未配置搜索服务时，明确告知用户“联网搜索尚未配置”，不能伪装成实时搜索。

### 文件问答

1. 上传接口校验文件；原始文件存入私有目录，元数据写入 `attachments`。
2. Parser 读取 PDF/DOCX/TXT/MD/代码文本；图片不走文本解析链路，交给视觉模型。
3. 对可提取文本的文件分块，保存到 `document_chunks`。
4. 用户提问时，只从当前用户可访问的文件中检索相关片段；首版关键词检索，Top-K 数量受配置限制。
5. 把片段及文件名/片段编号作为上下文交给模型，要求基于资料回答并说明资料不足时应承认不确定。

### 长期记忆

1. 用户在设置中开启记忆（默认关闭）。
2. 在满足阈值/节流条件的对话后，调用模型提取候选记忆；只保存稳定、对后续对话有帮助的事实/偏好，避免保存整段对话。
3. 用户可以查看、修改或删除单条记忆；关闭记忆后，不再新增/注入长期记忆。是否同时清空已有记忆应在 UI 提供明确选项。
4. 构建上下文时，按用户归属与相关性挑选有限数量的记忆，避免把全部记忆塞进每次请求。

### Agent 工具调用

- 统一工具结构：工具名、描述、输入参数 schema、执行函数、超时、输出限制。
- 首批工具：计算器（安全解析表达式，禁止 `eval`）、文档检索、联网搜索（仅配置后可用）。
- 限制每次任务工具调用步数、每个工具超时和结果长度；记录工具状态与错误。
- 不执行任意 shell 命令，不允许 Agent 直接访问任意本地路径。
- 若选定模型不支持原生 tool calling，需要在实现阶段评估结构化输出的替代流程；不能默认每个模型都有该能力。

## 6. 模型抽象设计

定义内部 `LLMProvider` 接口，避免业务服务直接依赖某家 SDK。建议方法：

- `chat(messages, options) -> ChatResult`
- `stream_chat(messages, options) -> AsyncIterator[StreamEvent]`
- `supports(capability) -> bool`，能力至少包含 `text_chat`、`streaming`、`vision`、`tool_calling`。
- 统一异常：认证失败、限流、超时、上游错误、能力不支持。
- 统一结果：文本、模型名、finish reason、服务商能返回时的 token usage。

服务商选定后再落地具体 adapter。若使用 OpenAI 兼容格式，也应以其实际文档和实际响应验证，不能只凭“兼容”名称假定所有字段、工具调用和视觉输入完全相同。模型密钥通过后端环境变量读取。

## 7. 外部依赖决策清单（目前未确定）

| 项目 | 当前处理 | 后续决策依据 |
|---|---|---|
| LLM API 服务商/模型 | 只定义抽象接口和环境变量 | 价格、网络可用性、中文质量、流式、视觉、tool calling、免费额度 |
| Web Search 服务 | `SearchProvider` 接口预留 | 价格/免费额度、地区可用性、来源质量、返回链接与摘要 |
| Embedding/向量数据库 | 首版不强制依赖 | 关键词检索测试效果不够时再选；比较本地方案与托管服务 |
| 文件对象存储 | 首版私有本地目录 | 云部署、备份、文件大小与费用 |
| 云服务器/域名 | 暂不选 | 预算、地区、部署环境、访问稳定性 |
| 前端 UI 组件库 | 尚未定 | 原生 CSS 足够时先不引入；需要加速时再选 |

## 8. 初始参数建议（可配置，不是外部服务承诺）

- 单文件大小上限先设为 20 MB，后续根据部署条件调整。
- 每次文档检索初始返回 Top-4 片段；片段长度与 overlap 放入设置项。
- Agent 每轮最多执行 3 次工具调用；具体工具各自设置超时与输出上限。
- 模型请求设超时、最大输出 token 和最近消息窗口；不要无限传送历史对话。
- 首版仅单机、本地私有文件目录；上线前必须补齐认证、限流、HTTPS、日志脱敏与备份。

## 9. 成功验收定义

- 本地能启动前端、FastAPI 与 MySQL，健康检查成功。
- 连续多轮对话可以保存、刷新后恢复，并且不同会话历史分离。
- 流式回答、停止、错误提示与重新生成可工作。
- 已选定且配置好的 LLM 能完成普通文本聊天；能力接口正确报告视觉/工具调用支持情况。
- PDF、DOCX、TXT/MD 和代码文件可解析并进行基础片段检索；无法解析的文件有明确错误状态。
- 配置了搜索服务后，搜索回答显示真实的标题/链接来源；未配置时不会假装搜索成功。
- 图片理解只在选定模型确实支持时开放。
- 记忆默认关闭；打开后可创建/管理，关闭后不再自动保存或注入。
- Agent 只调用白名单工具，步数有上限，异常时可结束并显示错误。
- README 可让另一个开发者了解依赖、环境变量、运行方式和已知限制。
