# AI 助手 V1：产品需求与技术方案

版本：0.2

定位：**豆包式网页版个人 AI 助手（视频除外）+ AI Agent 应用开发作品**

原则：每阶段可运行、可解释、有真实数据验收；Agent 工程深度优先于功能堆叠。

## 1. 项目定位与目标

### 1.1 产品定位

做一个网页版个人 AI 助手，交互参考豆包/ChatGPT：左侧会话列表，中间消息区，底部输入区。第一版覆盖日常问答、文件问答、联网搜索；后续补长期记忆、创作模式、图像理解、语音和 Agent 工具。产品形态以“自己每天愿意用”为标准，不做通用 SaaS。

### 1.2 双重目标

1. **产品目标**：豆包式个人助理，除视频处理外逐步补齐主要能力。
2. **学习目标**：为 AI Agent 应用开发校招/实习积累可演示、可解释、可评估的工程作品。Agent 能力（工具协议、循环、日志、记忆、评测、安全）优先于纯功能数量。

### 1.3 目标用户与场景

- **日常用户**：本人。每天用它总结文档、查实时信息、写作/润色、整理思路。
- **技术评审者**：校招/实习面试官。关注架构取舍、RAG/搜索质量、工具调用、异常处理、评测与安全。

### 1.4 成功定义

- 功能上：能连续聊天、上传文件并基于内容回答、联网回答带可点击来源、配置正确时能调用工具。
- 工程上：工具有协议和日志，Agent 循环有步数/超时，失败可恢复，关键路径有真实数据评测。
- 可信上：不伪造来源、不假装联网成功、不执行任意代码/Shell，越权访问被拒绝。
- 作品上：有可演示 demo、架构说明、评测报告和能讲清楚的取舍。

## 3. 功能架构

```
产品外壳（Web）
  ├─ 对话内核：会话、消息、流式、停止/重生成
  ├─ 上下文引擎：历史裁剪、文件片段、网页资料、记忆、预算/排序/引用
  ├─ 知识层：文件上传/解析/切块/检索、联网搜索/正文抽取/来源
  ├─ 个性化：长期记忆、设置、创作模式、自定义指令
  ├─ 多模态：图像理解、语音输入/朗读
  └─ Agent 层：工具协议、注册表、循环、tool_run 日志、工具状态
```

设计原则：对话内核稳定；知识层和 Agent 层通过明确接口接入；每层都有可独立测试的纯函数或协议。

## 4. 技术架构

### 4.1 技术栈（已确定）

| 层 | 选型 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite + Pinia + Vue Router + markdown-it + highlight.js；原生 CSS |
| 后端 | Python 3.12 + FastAPI + SQLAlchemy 2.x（async）+ Pydantic |
| 数据库 | MySQL 8.x，utf8mb4；Alembic 迁移 |
| 模型 | DeepSeek（OpenAI 兼容协议）为主；mock provider 供离线开发/测试 |
| 搜索 | Tavily 主源 + SerpApi 可选 fallback |
| 文件存储 | 本地私有目录；存储键由服务端生成 |
| 流式 | SSE（`text/event-stream`） |

### 4.2 后端分层

- `api/v1/endpoints/`：HTTP 层，只做参数校验、调用服务、返回响应。
- `schemas/`：Pydantic 请求/响应与 SSE 载荷。
- `services/`：聊天、会话、文件、搜索、记忆、Agent 编排。
- `repositories/`：SQL 查询；所有业务查询强制带 `user_id`。
- `models/`：SQLAlchemy ORM。
- `ai/providers/`：`LLMProvider` 抽象、mock、OpenAI 兼容 adapter；未来加视觉/工具调用能力。
- `rag/`：解析器、分块、检索、RAG 提示词组装。
- `search/`：Tavily/SerpApi adapter、主备切换、去重、时效与提示词组装。
- `storage/`：`StorageBackend` 抽象与本地实现。
- `tools/`：工具 ABC、注册表、计算器、文档检索、搜索工具（P2）。
- `core/`：配置、日志、错误、请求上下文。

### 4.3 前端结构

- `views/ChatView.vue`：页面组织。
- `components/chat/`：会话列表、消息列表、气泡、输入区、文件上传、来源、工具状态。
- `stores/`：会话/消息/流式状态、设置。
- `api/`：普通请求与 SSE 解析。
- `types/`：与后端 schema 对应的 TypeScript 类型。
- `router/`：聊天页；记忆/设置页在 P3 增加。

### 4.4 关键设计决策

1. **Provider 抽象**：业务层不直接依赖供应商 SDK；所有模型差异收敛到 adapter。
2. **SSE 事件**：`message_start`、`token`、`source`、`tool_status`、`message_end`、`error`；来源和工具状态可持久化到消息元数据。
3. **关键词 RAG 先行**：首版用中文二元组 + 英文/代码词 + 覆盖率/TF/短语/标题加权；不引入向量库，先验证效果。
4. **联网搜索**：Tavily 主源、SerpApi 可选备源；新闻/时效问题自动带 `topic/time_range`；摘要 + 发布日期进入提示词；失败不伪造来源。
5. **MySQL-only**：直接使用 `sqlalchemy.dialects.mysql` 类型，不做跨方言兼容。
6. **私有存储**：文件名不参与磁盘路径；`storage_key` 不返回客户端；路径穿越校验。
7. **单开发用户**：固定 dev user；所有查询按 `user_id` 过滤，为认证留位，但不等于完成多用户安全。
8. **元数据优先**：`metadata_json.sources` / `tool_statuses` 记录来源与工具终态，刷新历史可恢复。

### 4.5 数据与持久化

- 已建表：`users`、`conversations`、`messages`、`attachments`、`document_chunks`。
- 计划表：`user_settings`、`user_memories`、`tool_runs`。
- 文件正文在私有目录；数据库只存元数据与分块。
- 删除会话级联删除消息、附件、分块和磁盘文件。

## 5. 核心业务流程

### 5.1 普通聊天

1. 前端创建/选择会话，提交内容、可选附件、`search_mode`、创作模式。
2. 后端校验会话归属，先落用户消息与助手占位。
3. 上下文引擎裁剪历史，按预算拼装系统提示词、文件片段、网页资料、记忆（启用时）。
4. Provider 流式返回 token，SSE 转发；来源和工具状态在首个 token 前发出。
5. 正常结束保存完整回答、用量、来源；中断/失败保留部分内容与状态。

### 5.2 文件问答

1. 上传接口校验扩展名/大小/真实类型；文件写入私有目录，元数据入 `attachments`。
2. Parser 提取文本（PDF/DOCX/TXT/MD/代码）；分块入 `document_chunks`。
3. 用户显式附带 `attachment_ids` 时，只在这些文件中检索；总结类问题回退到文档代表片段。
4. 片段带文件名、片段号、章节进入提示词；回答必须引用来源，资料不足要承认。

### 5.3 联网搜索

1. 用户显式允许联网（`search_mode=auto`）；默认关闭。
2. 查询规划识别时效/主题（今天/最近一周/本月/今年、新闻/资讯），映射到 provider 参数。
3. `SearchProvider` 返回标题、URL、摘要、发布日期；结果去重、限流、失败切备源。
4. 搜索结果作为不可信资料进入 `<web_results>` 边界；提示词要求引用标题/URL、不执行网页指令。
5. SSE 发 `tool_status` 和 `source`；失败/空结果明确提示，不伪造来源。

### 5.4 长期记忆（P3）

1. 设置页默认关闭；用户显式启用后才写入/注入。
2. 对话后按阈值/节流提炼稳定偏好/目标/事实；不保存整段对话。
3. 支持查看、修改、删除、关闭；关闭后停止新增/注入；删除后不再召回。
4. 上下文按相关性与预算注入有限条记忆。

### 5.5 Agent 工具循环（P2 目标态）

1. 模型根据工具 schema 返回 tool call。
2. 注册表校验工具名、参数、权限、超时；执行并截断输出。
3. 工具结果以 tool 消息回填模型，继续推理；达到最大步数/超时/取消则安全结束。
4. 每次调用写 `tool_runs`，SSE 发 `tool_status`，来源与最终回答落库。
5. 工具只能白名单：计算器、文档检索、联网搜索；不执行任意 Shell/代码/路径访问。

## 6. Agent 工程能力（核心）

这一节是校招/实习作品的主线，不是附属功能。

### 6.1 工具协议与注册表

- `Tool` ABC：`name`、`description`、JSON Schema 入参、`run(args, context)`、超时、输出上限。
- `ToolRegistry`：白名单、按需启用、参数校验、统一错误、结果归一化。
- 首批工具：`calculator`（安全表达式解析，禁止 `eval`）、`document_search`、`web_search`。

### 6.2 Agent 循环与边界

- 单 Agent、有界循环：模型 → tool call → 执行 → tool 结果 → 继续/结束。
- 最大工具调用次数（`AGENT_MAX_TOOL_CALLS`）、单工具超时、总超时、取消传播。
- 模型不支持原生 tool calling 时，评估结构化输出替代；不能假装支持。
- 工具失败要能回填错误并让模型决定下一步，不能直接中断聊天。

### 6.3 工具运行记录与可观测性

- `tool_runs`：会话/消息、工具名、参数摘要、结果摘要、状态、耗时、错误。
- SSE `tool_status`：running/done/failed，前端展示执行状态。
- 请求 ID、工具日志、来源、用量一起构成可追溯链路。

### 6.4 记忆与上下文

- 记忆是上下文来源，也可作为工具；默认关闭、最小化存储、可删除。
- 上下文预算：系统提示词 + 历史 + 文件片段 + 网页 + 记忆，统一裁剪。
- 工具结果和网页内容都视为不可信数据，不能覆盖系统指令。

### 6.5 评测与回归

- 真实数据评测集：文件、搜索、工具选择、多步任务、失败恢复。
- 指标：召回、引用正确率、来源新鲜度/多样性、工具成功率、任务成功率、首 token 延迟、单轮成本。
- 每个阶段必须有真实数据验收；fake provider 只能证明流程，不证明质量。

### 6.6 安全边界

- 工具白名单、最小权限、参数校验、输出截断。
- 不执行任意 Shell/代码；不直接访问任意本地路径。
- 网页/文件内容防提示注入；URL 只接受 http/https；不服务端抓取任意用户 URL（P1 不做页面抓取时尤其注意）。
- 密钥只在后端；错误信息不泄露上游正文/密钥。

### 6.7 MCP 与插件（P6）

- MCP 客户端接入外部工具，工具描述/权限/超时与本地工具统一。
- 插件必须有 manifest、权限声明、启停开关和审计日志。
- 先做单 Agent + MCP，再做工作模式/多 Agent。

## 7. 质量与评测

### 7.1 真实数据评测集

| 类型 | 样例 | 关注点 |
|---|---|---|
| 文件总结 | 真实 DOCX/PDF，问“总结这个文件” | 是否读到正文、是否引用、是否承认图片/扫描件限制 |
| 文件细节 | 针对具体段落/数字提问 | 召回是否准确、片段号是否正确 |
| 文件对比 | 两份资料对比 | 多文件覆盖、来源区分 |
| 时效新闻 | “最近一周 AI 圈有什么新闻” | 日期新鲜度、来源多样性、是否单热点 |
| 实体动态 | “DeepSeek 最近发布了什么模型” | 官方源、时间范围、重复结果 |
| 常青知识 | “Transformer 和 Mamba 的区别” | 是否需要联网、来源质量 |
| 实时数据 | “英伟达最新股价” | 是否错误使用 web_search、是否明确限制 |
| Agent 工具 | 算数、查文件、查网页、组合任务 | 工具选择、参数、步数、失败恢复 |

### 7.2 指标

- 检索：Recall@K、来源正确率、无命中时是否诚实。
- 搜索：结果新鲜度、域名多样性、权威源占比、引用可点击率。
- Agent：工具选择准确率、参数合法率、任务成功率、平均步数、超时/失败恢复率。
- 体验：首 token 延迟、总耗时、单轮成本、错误可解释性。

### 7.3 质量门禁

- 没有真实数据验收，不把阶段标记为完成。
- 每次改检索/搜索/工具/提示词，至少回归本阶段评测集。
- 不允许用 fake provider 的绿灯替代真实质量结论。

### 7.4 当前已知缺口

- 文件 RAG 是关键词检索（中文二元组 + IDF + 标题路径），同义改写/跨语言召回仍有限；扫描件/图片不 OCR。
- 联网搜索正文依赖 Tavily `raw_content`；SerpApi 备源仍只有摘要；宽泛新闻可能只返回单一媒体，模型需明确说明来源不足；没有自建页面抓取器（避免 SSRF）。
- 旧上传不会自动重索引，解析/切块改进只影响新上传。
- 图片理解、语音、长期记忆、Agent 工具仍在计划中（P2–P4）。
- 前端缺分页加载、组件/E2E 测试；无 CI。

## 8. 非功能要求

- **安全**：密钥只在后端；上传校验扩展名/MIME/大小；服务端生成存储名；不执行用户代码；越权统一 404。
- **隐私**：记忆默认关闭；按 `user_id` 过滤；未完成认证/限流/HTTPS 前不公开给多人使用。
- **稳定性**：模型/搜索有超时与异常归一化；SSE 断开取消上游并标记中断；工具循环有步数/超时。
- **成本**：限制文件大小、片段数、搜索结果数、上下文预算、最大输出 token；记录用量；错误不泄露密钥。
- **可维护性**：API/服务/仓储/适配器分离；迁移管理表结构；文档与代码状态同步。
- **可测试性**：单元测试不依赖真实 API；集成测试用真实 MySQL；关键外部能力用 MockTransport/fake provider；真实数据评测单独跑。

## 9. 开发工作流（VSCode + Claude Code）

1. **先写验收标准**：每个阶段先明确功能、工程、评测三类验收，再写代码。
2. **Claude Code 用 plan mode**：先让它读代码/文档、给出方案，再执行；避免一次性生成大量难解释代码。
3. **垂直切片**：一次只做一个端到端可运行的小功能（API + service + 前端 + 测试）。
4. **测试分层**：纯函数单测 → MySQL 集成测试 → 真实数据评测；不把 fake 绿灯当质量结论。
5. **小步提交**：每完成一个可运行切片提交一次；提交信息说明行为变化。
6. **文档同步**：状态、API、表结构变化同步到 `docs/`；本阶段优先保证 PRD/路线图/README 一致。
7. **密钥边界**：只放 `backend/.env`（Git 忽略）；不粘贴到聊天、不写进前端 `VITE_*`、不提交。
8. **代码评审**：用 `code-review`/`simplify` 类检查找回归和过度设计；先修正确性再优化。

| 部署 | 开放 | P5 再定云服务器/域名/HTTPS/备份 |
| UI 组件库 | 开放 | 原生 CSS 够用则先不引入 |
| MCP | 开放 | P6 评估客户端/工具接入 |

## 12. 风险与开放问题

- **搜索质量**：摘要深度、来源权威性、宽泛新闻的多样性；需要正文抽取/查询规划/评测。
- **模型能力**：不同 provider 的 tool calling、视觉、流式细节不同；必须以真实响应验证。
- **成本/延迟**：多查询、读正文、语音会增加成本；需要预算、超时、缓存。
- **隐私/安全**：记忆、文件、网页内容都涉及敏感数据；公开部署前必须补认证/限流/HTTPS。
- **范围膨胀**：豆包式功能很多；以 Agent 深度优先，避免每个功能都做一半。
- **时间**：校招/实习准备期有限；每阶段必须有可演示产出，不能长期停留在基础设施。
